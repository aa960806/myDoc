# Codex 桌面端与多对话协作

适合已经完成本站 Codex 接入、希望继续学习桌面使用的用户。公开文档查阅日期：2026-11-04。菜单、工具与快捷键以使用时的客户端和配置为准；本轮没有替教学账户创建对话、发送跨对话任务或执行收费模型调用。

网页入口：`#tool/codex?part=desktop`。操作关系配图为示意，不是客户端实测截图。

## 开始前

- 准备一个本地练习目录 `agent-practice`。
- 已有第一次任务生成的 `learning-plan.md`；没有时，先回 `#tool/codex?part=start&section=agent-task`。
- 完成后能选择合适的对话方式，保存并重新打开对话链接，说明每位参与者的范围，并找到最终文件。
- 学习顺序：认清工作区 → 分叉和链接 → 按需用子对话或子代理 → 核对协作成果。

## 1. 项目、对话和文件分别做什么

项目决定这次要处理哪一组文件，对话用来交代目标与要求，文件面板和系统编辑器用来检查真实产出。

1. 在项目入口选 `agent-practice`。Windows / Linux 可用 `Ctrl + O`，macOS 用 `⌘ + O` 打开文件夹。
2. 确认是本地电脑上的正确目录。一个项目关联多目录时，检查主要目录。
3. 输入 `/model`，从可用列表选择模型；需要时用 `/reasoning` 调整思考强度。本站模型权限仍取决于密钥分组。
4. 看输入框附近的权限控件。文件操作提示出现时，按具体路径与动作判断。本课只需要练习目录中的文件读写。
5. `/status` 可查看对话 ID、上下文用量等状态；实际本站消费去本站使用记录核对。

先发送一个只读任务：

```text
请先确认当前工作目录，并只读检查 learning-plan.md。
告诉我文件是否存在、标题是什么、有几个学习步骤。
先不要修改文件；若文件不在当前目录，请说明你实际检查的路径。
```

打开回复中的文件链接，在文件面板或系统编辑器中核对。然后再提出一个明确修改，例如只修改标题。实际文件与路径正确，才算完成。

当前官方文档称桌面产品为 ChatGPT desktop app，其中提供 Codex；部分客户端版本仍使用 Codex 名称。本课针对能操作本地项目的 Codex 入口。

## 2. 继续、新建和分叉

| 方式 | 适用情形 |
| --- | --- |
| 继续当前对话 | 同一个目标未结束，或修正刚才的结果。 |
| `/new` | 开始独立目标；当前环境支持时，在同一本地工作区开始空白对话。 |
| `/fork` | 需要沿用已有背景，但希望试另一种方案。复制当前本地对话，随后分别推进。 |

分叉练习：

1. 原对话已经确认一周学习计划的目标与约束。最好等本轮任务结束，方便辨认结果。
2. 输入 `/fork`，从命令列表选择，按界面选本地新对话或工作树。
3. 进入新对话，用 `/rename` 命名为“学习计划 · 15 分钟版”；原对话命名为“学习计划 · 原方案”。
4. 在新对话发送：

```text
沿用前面的一周学习目标，另外拟一份每天 15 分钟的版本。
先在聊天中展示方案，与原方案比较。
此时不要修改 learning-plan.md，也不要改动其他文件。
```

分叉聊天不会自动隔离磁盘文件。同目录下的两条对话可能修改同一份文件；分叉也不等于创建 Git 分支、复制项目或撤销磁盘改动。保存两版可用不同文件名，需要隔离代码时再使用工作树。

## 3. 复制对话深度链接

1. 先打开要保存的那条对话，核对标题。
2. Windows / Linux 默认按 `Ctrl + Alt + L`；macOS 默认按 `⌘ + ⌥ + L`。也可在命令菜单找 **Copy chat deep link / 复制对话深度链接**。
3. 在自己的任务清单中写上标题，粘贴实际复制的链接。典型形式为 `codex://threads/实际对话ID`，不能照抄示例 ID。
4. 在能访问这条对话的电脑上点击链接，按系统提示打开客户端，再核对标题与内容。

快捷键可在 **Settings → Keyboard Shortcuts** 查询或修改。它用于定位对话，不会发布公开网页、授予他人账户和文件权限，也不会持续同步两条对话的消息。另一台设备缺少目标对话或相应环境时，链接不能带走整个本地项目。

## 4. 临时子对话 `/side`

Side chat 是不打断主对话的临时旁支，适合解释一个概念。它与负责执行分工的子代理不同。

1. 在主对话输入 `/side` 并选择该命令。默认快捷键：Windows / Linux `Ctrl + Alt + S`；macOS `⌘ + ⌥ + S`。
2. 提一个小问题：

```text
请用新手能理解的话解释 Markdown 文件和普通文本文件的关系。
给一个标题和待办项的小例子，只在聊天里说明，不创建或修改文件。
```

3. 回到主对话。新结论会影响任务时，明确补充“计划请使用 Markdown 标题和待办项”。不要假定旁支里的要求已经变成主对话的要求。

| 方式 | 用途 |
| --- | --- |
| 临时子对话 `/side` | 临时解释、概念确认、小问题。 |
| 侧栏普通新对话 | 独立、会继续推进的目标。 |
| 子代理 Subagent | 委派一部分工作，主对话等待并汇总。 |

没有 `/side` 时，可在普通新对话提问并手动带回结论，无需修改本站 API 配置。

## 5. 两个子代理分头检查

先有 `learning-plan.md` 成稿，再让两位只读检查不同维度。主对话等齐结果，负责结论与后续修改。

```text
请使用两个子代理，只读检查当前目录的 learning-plan.md。
子代理 A：检查是否有明确目标、每天安排与完成标准。
子代理 B：检查每天用时是否合理，是否存在互相矛盾或重复的要求。
两位都不要修改文件，只返回问题位置、原因和建议。
请等待两位都完成，再由你在主对话合并结论，去掉重复项。
本轮先给我检查结果，不改文件；文件不存在时直接说明，不要猜测内容。
```

当前客户端显示子代理活动或关联对话时，打开查看状态与结果。主对话应保留分歧和证据，不能把所有建议自动当作正确结论。确定采用哪些建议后，再由一位负责修改文件。

分工要求应说清各查什么、可不可以写文件、何时汇总。子代理分别使用模型与工具，可能增加用量；“只读”任务要求不等于单独建立了只读沙箱，实际访问范围由父对话权限和工作区决定。没有子代理能力时，可依次检查，或用普通对话手工分工。

## 6. 让已有对话相互配合

为已有对话明确命名、文件和职责：

- “学习计划 · 初稿”：写 `learning-plan.md`。
- “学习计划 · 审查”：初稿完成后只读审查，输出问题清单。
- “学习计划 · 汇总”：依据初稿与审查结论，写 `learning-plan-final.md`。

审查依赖初稿，不能在文件还没完成时当作已检查。同一个项目不代表所有聊天历史自动混合。

当前客户端提供跨对话管理工具时，可将实际深度链接交给汇总对话。先只读了解进度：

```text
请先只读查看下面两条对话的进展，暂时不要给它们发送消息，也不要修改文件。
初稿对话：在这里粘贴实际深度链接
审查对话：在这里粘贴实际深度链接
请分别说明：当前目标、是否完成、产出文件、尚未解决的问题。
若当前客户端无法读取这些对话，请告诉我需要手动提供哪些摘要，不要假设你已经读到了。
```

需要交接指令时，明确接收对象、发送内容和允许范围：

```text
初稿已完成，请向“学习计划 · 审查”（在这里粘贴实际深度链接）发送这条任务：
“请只读检查当前项目中的 learning-plan.md，列出目标、时间安排和完成标准的问题；不修改任何文件。”
我授权你向这条审查对话发送上述任务。
发送后请在当前对话等它完成，再把审查结果与初稿合并说明；先不要改稿，也不要给其他对话发消息。
```

不能读取或联系另一条对话时，分别请它们给出摘要，再手工粘贴给汇总对话：

```text
请为另一个对话整理一份交接摘要：
1. 本次目标和已经确认的约束。
2. 实际完成了什么。
3. 产出文件的完整路径，以及是否已保存。
4. 做过哪些检查，结果是什么。
5. 仍存在的问题、分歧和下一步建议。
不要包含密钥、密码或其他无关的个人资料。
```

## 7. 共享目录与工作树

同一本地目录里的对话可能读写同一批文件。首次练习采用一位编辑、其他只读，或分开写不同文件。没有 Git 的独立方案可放进不同的普通练习目录。

已有 Git 项目需要并行修改时：

1. 新对话中，在输入框下方选择 **Worktree / 工作树**。
2. 选择起始分支，提交任务。
3. 客户端创建工作树后，核对新目录，在那里检查与验证成果。
4. 准备好后，走 **Hand off / 移交** 回本地，或保留工作树并通过分支、代码审查整合。

工作树提供 Git 工作副本，不是聊天背景的合并工具，也不保证被忽略的环境文件一起出现。不要同时让两条对话操作同一目录的 Git 分支、恢复、合并。冲突时先暂停相关写入，比较现状，再明确一位负责人。

## 8. 完成一轮初稿、审查与汇总

选择子代理方式或普通对话方式之一即可。已有初稿时直接审查；最后在汇总对话发送：

```text
请先读取当前目录的 learning-plan.md，以及我们已经确认的审查结论。
仅采用已经确认的建议，将最终版本保存为 learning-plan-final.md。
保留原稿；如果目标文件已存在，先说明现状，不直接覆盖。
完成后检查：标题、每天安排、用时和完成标准是否完整，文件是否真实保存。
请给出完整文件路径、采用了哪些建议，以及还有哪些未解决的问题。
```

完成检查：

1. 在电脑上打开最终文件，核对保存路径。
2. 与原稿比较，确认建议落实且目标未意外改变。
3. 重命名各对话，保存汇总对话深度链接；暂时结束的对话可归档。
4. 在本站使用记录按时间、密钥、模型核对费用。多个对话或子代理可能对应多次请求。

常见卡点：

- 没有 `/fork`、`/side`：看本地 Codex 输入框的实际 `/` 列表，桌面与 CLI 命令表不同；用新对话与摘要兜底。
- 快捷键被占用：让客户端获得焦点，在 Settings → Keyboard Shortcuts 查动作名称。
- 链接打不开：重新复制实际链接，核对客户端、目标对话和环境可访问性；必要时交接摘要。
- 分叉后原文件变了：核对两边是否共用目录。原对话不是磁盘恢复点，先比较文件现状。
- 协作结果混乱：检查是否重复写同一文件、审查是否过早、是否有一个人负责最终收尾。
