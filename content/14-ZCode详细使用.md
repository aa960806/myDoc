# ZCode 详细使用教程

更新：2026-11-04

从连接本站模型开始，学会选工作区、给材料、看计划和检查修改。再用辅助对话、分叉与子智能体，把一项任务有条理地做完。

准备：本站普通 Claude 分组 API Key；电脑上的一个空 `agent-practice` 文件夹。

学习路线：安装与配置 → 选择工作区 → 创建学习计划 → 检查和修正 → 管理任务与复用流程。

## 01 先认识工作台（agent-fit）

ZCode 是有图形界面的 Agent 工具。工作区决定文件在哪，模型决定调用哪项服务，任务保存讨论过程，文件树用来检查成果。本课沿用本站 Claude 分组和 Anthropic 兼容接口。

先连接模型，再打开文件夹，确认计划后动手，最后检查文件和本站记录。供应商与 API Key 决定请求发到哪里；本课单独添加只因 API 通道。

## 02 下载与首次启动（agent-download）

1. 打开 [ZCode 官方安装页](https://zcode.z.ai/cn/docs/install)，按当前页面下载。普通 Intel / AMD Windows 电脑选 x64，ARM 设备选 ARM64；macOS 按 Apple Silicon / Intel 选择，Linux 按发行版选安装包。
2. 启动后点击“开始使用 ZCode”。首次可以跳过数据迁移。
3. 没有模型时，点击左下角“连接使用 → 使用 API Key”。已进入应用时，点输入框旁模型名称 → 列表底部“管理模型”，进入“设置 → 模型设置”。

Windows 当前版本可在关闭窗口时隐藏到托盘。需要完整重启时，从托盘右键菜单退出后重新启动。“设置 → 常规 → 通知”可调整关闭行为。

完成标准：能打开 ZCode，并找到模型设置。

## 03 连接本站与切换模型（agent-connect）

先在 [本站密钥页](https://www.yydsapi.uno/keys) 准备普通 Claude 分组 Key，在 [模型广场](https://www.yydsapi.uno/model-plaza) 核对该 Key 可调用的完整模型 ID。

进入模型设置 → 添加供应商，选择 Anthropic 兼容接口：

| 字段 | 本课示例 |
| --- | --- |
| 名称 | 只因 API · Claude |
| Anthropic 接口地址 | `https://www.yydsapi.uno` |
| API Key | 在 ZCode 本地粘贴自己的完整 Claude 分组 Key |
| 添加模型 → 模型 ID | `claude-sonnet-4-6`，按本站当前实际支持调整 |

保存后添加模型并开启供应商的“启用”开关。此 Anthropic 路线填写根地址，不追加 `/v1/messages`。

回到任务，点模型选择器，选“只因 API · Claude”下的模型。Windows 快捷键为 `Ctrl + M`，Mac 为 `Control + M`。先使用默认思考档位，再发送：

```text
你好，请用一句话说明你可以怎样帮助我整理一份学习计划。
```

收到回复后，在本站使用记录核对时间、模型与 Key。保存供应商只代表配置写入，回复及对应使用记录才能证明这次调用情况。

切换模型应等当前任务结束。模型名称旁的思考图标用于调节该模型提供的档位；第三方部署对参数的支持可能不同。遇到思考参数 400 报错，先恢复已验证的默认档位。更换供应商时一起核对分组、协议、基础地址、模型 ID，不统一为所有地址追加 `/v1`。

## 04 工作区、权限与文件引用（agent-workspace）

在电脑文档目录创建空的 `agent-practice`。通过 ZCode 工作区入口或左侧顶部搜索中的“打开文件夹”选择它。核对界面显示的目录。“不在项目中工作”适合问答；本课要保存文件，请选练习工作区。

输入框附近选择执行模式；聚焦输入框时可按 `Shift + Tab` 切换：

| 模式 | 用法 |
| --- | --- |
| 计划模式 | 先了解文件并给方案，确认计划后实施 |
| 变更前确认 | 默认档位；修改文件或执行命令前询问，适合首次练习 |
| 自动编辑 | 文件编辑可自动执行，命令等仍按规则确认 |
| 完全访问 | 减少文件与命令操作的确认；先理解操作范围 |

先用计划模式对齐目标，写入文件时使用变更前确认。审批时看清路径和动作。

输入 `@` 从列表选择文件或文件夹，也可以从“＋”添加附件。文件生成后再发送：

```text
@learning-plan.md 请概括这份计划的目标、三个练习和完成标准，只阅读，不修改。
```

长期要求放在当前工作区的 `AGENTS.md`。ZCode 持续读取用户级 `~/.zcode/AGENTS.md` 与当前工作区的 `AGENTS.md`，不逐层扫描子目录规则。`CLAUDE.md` 只可能在首次迁移时复制成 `AGENTS.md`，后续不是持续读取的规则来源。已有规则先检查合并，再加入要求。

## 05 完成第一次文件任务（agent-task）

以下内容发送到 ZCode 任务输入框，逐步完成。

### 第一步：确认目录和方案

```text
请先确认当前工作区是 agent-practice，并列出已有文件。
我想创建一份面向零基础用户的 AI 学习计划，包含提问、总结、修改结果三项练习，每项 5 分钟，每项有具体动作和完成标准。
请先说明你准备写入的文件名、结构和检查方式，暂不修改文件。
如果 learning-plan.md 已存在，请先告诉我，不要覆盖。
```

### 第二步：确认计划后写入

确认路径和内容正确，再按界面确认计划，切到“变更前确认”并发送：

```text
按刚才确认的计划，在当前 agent-practice 工作区创建 learning-plan.md。
标题为“我的 AI 学习计划”，正文使用中文 Markdown。
保留原有文件，不覆盖任何已有同名文件。
完成后检查三个练习是否各有动作、用时与完成标准，并告诉我实际保存路径。
```

### 第三步：打开真实文件

点击工作区卡片右侧文件树图标 / “查看文件”。单击 `learning-plan.md` 在右侧预览；双击或 Enter 使用默认编辑器。右键可以添加到聊天、复制路径或在资源管理器中打开。

### 第四步：只修改标题

```text
请只把 learning-plan.md 的标题改为“我的第一周 AI 学习计划”。
保留三个练习的正文、用时与完成标准。保存后说明改了哪一处，并告诉我文件路径。
```

完成标准：文件能打开，标题已更新，三个练习与完成标准保持完整。

## 06 任务管理、辅助对话与分叉（zcode-sessions）

同一目标继续原任务；独立工作新建任务。Windows `Ctrl + N`、Mac `⌘ + N` 新建。左侧有工作区、分组、时间线视图，放大镜可以搜索会话和文件。

切到“分组”视图 → 新建分组 → 命名“AI 学习练习”，把任务拖入或右键“移动到分组”。完成后可归档，在归档列表取消归档找回。

### 临时问一个问题

在已有主会话的桌面输入框选择 `/side` 或 `/btw`，也可用右侧“＋ → 辅助对话”。在辅助对话中发送：

```text
请用新手能理解的话解释 Markdown 文件是什么，举一个标题和勾选清单的例子。只解释，不修改文件。
```

辅助对话能借用主会话历史，仍有工具能力且共享当前文件，并非天然只读。关闭辅助标签、归档/删除主任务、退出应用后不可恢复，重要结论带回主任务或保存成文件。

### 试另一个方案

鼠标移到一条稳定完成的助手回复，点“分叉”。新任务形如 `Fork of 原标题`，继承分叉位置之前的历史，原任务保留。在新任务中发送：

```text
参考 learning-plan.md，另拟一份每天总共 10 分钟的精简计划，保存为 learning-plan-short.md。
保留原文件，不改其他文件；目标文件已存在时先告诉我。
完成后列出两个版本在时间安排和练习内容上的区别。
```

分叉不会回滚文件，不复制进行中的工作与队列。两条任务仍共享工作区，因此用不同输出文件保存方案。

需要旧背景时输入 `#`，从列表选历史会话，再说明要沿用哪些内容。长对话可用 `/compact` 整理上下文，重要约束仍保存为文件。引用不代表任务持续同步。

## 07 检查修改与恢复文件（zcode-review）

打开原版与精简版，比较目标、用时、完成标准。Git 项目可在文件树开启“仅显示变更文件”。Git 标记可能包含此前工作，按内容分辨本轮变化；Git 图主要用于查看历史，不替代文件内容比较。

把两份文件添加到聊天，再只读检查：

```text
请阅读 learning-plan.md 和 learning-plan-short.md，逐项检查：
1. 是否面向零基础用户；
2. 每个练习是否有动作、用时和完成标准；
3. 精简版是否满足每天总共 10 分钟；
4. 是否有矛盾或重复。
请列出文件名、问题位置与修改建议，先不要改文件。
```

代码项目请先让 Agent 读 README 和脚本，确定与改动有关的检查，再运行并明确报告通过、失败、未运行。

### 最后一句要求写错

任务空闲且没有队列时，可编辑最后一轮用户消息。查看“对话 + 文件重置”恢复提示；“仅重置对话并发送”不还原文件。编辑队列消息会将其退回输入框，需要重新发送。

### 文件改错

每轮回复下方“文件变更摘要 → 撤销”会先列出可恢复、无法恢复和忽略的文件。确认后才写回，成功后可重新应用。某个文件无法安全恢复时，不会只撤销其中一部分。

终端命令改动会被忽略；没有保留原内容或被手动修改过的文件也可能不在可恢复范围。用 Git 或已知备份检查这些改动。停止任务、关闭窗口、分叉不会自动撤销磁盘文件。

## 08 子智能体、技能与自动化（zcode-extensions）

### 从两个只读子任务开始

Explore 用于只读探索，general-purpose 可执行更完整工作。发给主任务：

```text
请使用两个 Explore 子智能体，只读检查当前工作区的两份学习计划。
A：对照 learning-plan.md，检查 learning-plan-short.md 是否保留了关键学习目标。
B：检查精简版的总用时是否为 10 分钟，各项完成标准是否可检查。
两位都只读文件、不联网、不修改。等结果都回来后，在主任务合并问题和建议，不要直接修改成稿。
```

前台任务需要等结果，后台任务完成后结果回主会话；具体方式由 Agent 安排。收齐后由一个负责人修改。支持自定义子智能体的版本，可在“设置 → 子智能体 → 新建”保存角色。检查角色选择继承模型与读取工具，保存后新建会话使用。该功能仍有 Beta / 灰度条件，无入口时使用内置 Explore。

### 保存常用命令

Command 保存常用提示词；Skill 复用方法与辅助材料；MCP 连接外部工具或数据；Plugin 把多项能力组合分发。

进入“设置 → 命令 → 新建命令”，选工作区作用域，名称 `check-plan`，内容：

```text
请只读检查当前工作区的学习计划，核对目标、步骤、用时和完成标准。列出文件名、问题位置及建议；没有文件时明确说明。不要修改文件。
```

保存后输入 `/check-plan` 从列表选用。

### 技能与 MCP

“设置 → 技能”查看来源、刷新与启用。输入 `$` 选择，也可以在 `/` 面板的技能分组选择。内置配置向导可用时：

```text
$zcode-configuration-guide 我想为这个工作区建立一个检查学习计划的命令，请先说明创建入口、作用域和使用方式，暂时不要修改文件。
```

“设置 → MCP 服务器 → 新建 MCP 服务器”，选作用域，再按目标服务的官方文档选 stdio / HTTP / SSE，填写命令或 URL。保存并启用，核对连接状态；OAuth 服务点“去授权”。导入已有配置后也要检查作用域和目标。本站模型凭据不等于外部服务登录。新增工具后开新会话确认可用。

### 定时任务与记忆

先手动完成流程，再到本地项目左侧“自动化 → 创建定时任务”。填写标题、时间、指令，核对项目、权限、模型和推理强度。使用电脑本地时区，核对下次运行时间。“立即运行”可测试，“历史”看结果，不再需要时暂停或删除。电脑需要唤醒、应用需要运行。本站模型调用照常计费。

“设置 → 常规 → Memory”默认关闭，开启后对新会话生效。它积累项目事实，与手写 AGENTS.md 不同，会增加模型用量。当前官方文档说明尚无 UI 查看或清除入口，重要规则维护在可检查的 AGENTS.md 中。

## 09 成果与费用核对（agent-check）

1. 原版、精简版都保存在练习目录并能打开。
2. 内容满足要求，知道本轮修改了什么。
3. [本站使用记录](https://www.yydsapi.uno/usage) 中的 Key、模型与时间对应本次任务。

规划、生成、审查、子智能体和记忆都可能产生多次请求。客户端统计和模型自报名称不能替代本站对应 Key 的结算记录。

## 10 常见卡点（agent-help）

| 现象 | 下一步 |
| --- | --- |
| 模型列表没有本站模型 | 确认供应商启用、已添加完整模型 ID，再回任务选中模型 |
| 401 / 403 / 400 / 404 | 核对普通 Claude 分组 Key、根地址、Anthropic 协议、模型 ID；思考参数恢复默认后按错误码排查 |
| 只给计划不写文件 | 检查计划确认与审批，明确保存路径，完成后打开文件 |
| 没有辅助对话、分叉或编辑按钮 | 检查桌面已有会话、助手回复是否稳定完成、最后一轮用户消息是否空闲无队列 |
| 分叉后两边改同一文件 | 停止冲突写入、检查磁盘内容，改用不同文件名或独立目录 |
| 撤销无法安全恢复 | 阅读无法恢复和忽略列表，使用 Git 或已知备份核对 |
| 技能 / MCP 不生效 | 查作用域、来源、启用与连接；开新会话，技能可通过 `$` 选择 |
| 终端联网而应用请求失败 | 查看设置 → 常规的 HTTP 代理；模型请求不是自动继承系统 HTTP_PROXY，修改后完整重启 |
