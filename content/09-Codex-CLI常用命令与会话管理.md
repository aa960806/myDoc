# 把 Codex CLI 用顺手

页面入口：`#tool/codex?part=cli`。本课归属「Agent 与工具 → Codex」。

本次官方文档核对：2026.11.04。没有为本课安装或升级客户端、修改本机配置或发起付费模型请求；菜单、模型与工具能力按实际版本、配置和本站分组核对。

## 开始前

- **准备：** 已完成 GPT 准备课的 CLI 安装与本站配置，准备 `agent-practice` 练习文件夹。
- **完成后：** 能切换模型、查看状态，知道命令输入位置，能恢复或分叉一条聊天，并检查文件与本站用量。
- **顺序：** 启动 → 核对模型与目录 → 完成小任务 → 检查成果 → 退出与恢复。

## 01 分清两个输入位置

| 位置 | 输入什么 |
| --- | --- |
| PowerShell，出现 `PS C:\…>` | 启动和管理程序：`Get-Location`、`codex.cmd`、`codex.cmd resume`。 |
| 启动后的 Codex 任务输入区 | 中文任务，以及 `/model`、`/status` 等斜杠命令。输入 `/` 查看菜单。 |

从资源管理器进入 `agent-practice`，点击地址栏，输入 `powershell` 并回车。在 PowerShell 依次执行：

```powershell
Get-Location
codex.cmd --version
codex.cmd
```

本站原安装课使用 Windows + npm，因此写 `codex.cmd`。其他官方安装方式使用其实际提供的 `codex` 命令。版本、平台、权限设置及功能开关可能影响可用菜单。

**完成检查：** 能说明启动命令与斜杠命令分别输入在哪里。

## 02 用 /model 切换模型，再核对状态

等当前任务结束，在 Codex 输入区：

1. 输入 `/model`，回车。
2. 从实际列表中选模型；界面提供时，选择该模型支持的推理强度。
3. 输入 `/status`，核对模型、审批策略、可写目录、上下文和 token 情况。
4. 输入 `/permissions`，按当前练习查看文件访问和审批方式。

模型列表取决于客户端、供应商配置和模型目录。本站能否调用，还取决于密钥分组和模型权限；切换名称不会获得新权限。找不到目标时，核对本站模型广场和配置课，不照抄他人的模型名。

只读模式适合解释文件；保存本课计划需要允许练习目录内的写入。权限设置控制访问范围，任务中“只改这一个文件”说明本次具体要求。

可选直接参数（以模型支持为前提）：

```text
/model --reasoning=high
```

它保留当前模型，在模型支持时设为 high。并非每个模型都有相同强度，也不意味着固定速度或固定费用。初学优先用菜单。

**完成检查：** `/status` 中模型和目录正确，知道本次是否允许修改文件。实际接入和费用继续通过任务与本站记录核对。

## 03 常用命令速查

均输入 Codex 任务输入区，页面提供只复制命令自身的按钮。

| 命令 | 用途与边界 |
| --- | --- |
| `/model` | 切换模型与可用推理强度；之后用 `/status` 核对。 |
| `/status` | 查看模型、审批策略、可写目录和上下文；不是本站实扣账单。 |
| `/permissions` | 调整访问范围与审批方式；只读模式不能保存文件。 |
| `/plan` | 先讨论计划；当前任务运行时暂不可用。 |
| `/mention learning-plan.md` | 引用已有文件，从匹配列表选中后再交代任务。 |
| `/diff` | 显示 Git 改动，包括已暂存、未暂存与未跟踪文件。 |
| `/review` | 用模型审查工作树，可能产生用量；不等于已经修复或跑完测试。 |
| `/new` | 开新聊天；不会自动撤销或删除磁盘成果。 |
| `/resume` | 恢复保存的聊天。 |
| `/fork` | 从当前上下文分叉；文件是否隔离取决于目录或 worktree。 |
| `/compact` | 将早期对话压缩成摘要，腾出上下文。 |
| `/copy` | 选择最近完成的回复、代码或引用复制。 |
| `/quit`、`/exit` | 退出 CLI；之后可 resume。 |

### 输入与跟进按键

| 按键 | 用途 |
| --- | --- |
| `@` | 搜索工作区文件并加入提示。 |
| ↑ / ↓ | 找回输入草稿历史。 |
| Ctrl+R | 搜索提示历史；Enter 使用结果，Esc 取消搜索。 |
| Ctrl+O | 复制最近已完成的回复。 |
| 运行中输入要求，按 Enter | 将补充要求加入当前工作。 |
| 运行中输入要求，按 Tab | 排队到下一轮，等当前工作结束后处理。 |
| 空输入框，Esc 连按两次 | 编辑上一条用户消息，并从该位置分叉；不自动回滚文件。 |
| Ctrl+C | 官方参考列为关闭 CLI 会话；可使用 `/quit` 明确退出。 |

按键受菜单、终端和自定义键位影响。空输入状态按 `?` 查看当前提示。不要把“退出”和“暂停”“文件回滚”混为一谈。

## 04 新建、恢复与分叉

- **同一件事继续做：** `/resume`，沿用原保存聊天。
- **完全不同的事情：** `/new`，从新上下文开始。
- **相同背景试另一方案：** `/fork`，得到新聊天，保留原聊天历史。

先给聊天命名：

```text
/rename 学习计划练习
```

聊天名不会更改文件名。下次进入原练习目录，在 PowerShell 恢复：

```powershell
codex.cmd resume
```

已经打开 Codex 时直接 `/resume`。选择器 Cwd 查当前目录，All 跨目录；Repo 如有，覆盖关联 worktree。保存的目录与当前目录不同时按提示核对后选择。

可选 PowerShell 命令：

```powershell
# 当前目录最近一条
codex.cmd resume --last

# 选择旧聊天并分叉
codex.cmd fork

# 分叉当前目录最近一条
codex.cmd fork --last
```

### 分叉练习

输入 `/fork`，按当前界面选择当前目录或独立 worktree。发给新聊天：

```text
请参考 learning-plan.md，把安排精简为两步，另存为 learning-plan-short.md。保留原文件。如果目标文件已存在，先告诉我，不要覆盖。完成后说明两个版本的区别。
```

两条聊天选择同一个目录，就共享该目录的文件。练习用不同文件保存方案；同时修改代码项目时再学习 worktree。不要让两条聊天同时改同一个文件。

### 按需展开的进阶入口

- `/side`（别名 `/btw`）：临时旁支，记录与主聊天分开；例如 `/side 用三句话解释 Markdown 标题的写法`。review 模式或已有旁支里面不可用。
- `/agents`：会话中心，依赖共享本地或远程服务器。查看并切换聊天，不会自动拆分任务。
- `/subagents`：查看或继续已经委派的子代理工作，不是自动生成多位代理的按钮。

委派用明确的自然语言任务：

```text
请将这份计划交给两个子代理检查：一位只检查步骤是否完整，一位只检查表达是否适合新手。都只阅读，不修改文件。由主对话汇总结果，给我一份去重后的修改清单。
```

能力以当前客户端与设置为准，并行任务可能产生多次模型请求。简单工作在一条聊天里完成即可。

**完成检查：** 知道选哪种会话操作，并能说明每条聊天将改哪个目录、哪个文件。

## 05 计划、差异与审查

先确认目标时，在 Codex 输入：

```text
/plan 我想把学习计划改得更适合完全没有基础的人。先说明要改哪些地方和检查标准，等我确认后再执行。
```

读完计划并补充条件；准备执行时，按当前界面切回允许执行的模式，再要求修改。计划文本不是已经落盘的成果。

在 Git 项目里用 `/diff` 查看新增、删除和修改。普通文件夹直接在资源管理器打开修改前后的两个文件比较，不必为了首练立即配置 Git。

用 `/review` 按菜单选择未提交改动、某次提交或相对基础分支的差异。模型审查可能产生本站用量；发现问题后再决定修复，并运行项目实际检查。

**完成检查：** 能指出改了什么，以及用了什么方法确认正确。文档要打开看内容，代码要看差异并运行适当检查。

## 06 文件、技能与 MCP

1. 用 `@` 搜索文件，或 `/mention learning-plan.md`，从匹配结果选中。
2. 说明具体要求，例如：

```text
请只阅读这份计划，用三句话说明它的目标、步骤和完成标准。先不要修改文件。
```

3. 重复的专业任务可用 `/skills` 选择相关技能，再交代任务；普通文件练习不要求额外技能。
4. 需要外部服务能力时用 `/mcp` 查看现有连接；用 `/mcp verbose` 查看详细诊断，再按该服务说明配置或登录。

技能提供工作方法与指令，MCP 提供外部工具连接。它们不会替代模型或增加本站分组权限。查看列表也不会自动安装和登录所有服务。

**完成检查：** 能明确说明“看哪个文件、做什么、是否允许修改”。

## 07 完整小练习与排错

沿用 Codex 首课已生成的 `learning-plan.md`：

1. 从练习目录启动，`/status` 核对目录和模型。
2. `/model` 选本站分组支持的模型，再 `/status` 确认。
3. `@` 或 `/mention` 引用计划，只读解释。
4. `/fork`，另存精简版 `learning-plan-short.md`。
5. `/rename 计划精简版`，打开两份文件比较。
6. `/quit` 后，在 PowerShell 用 `codex.cmd resume` 找回。
7. 到本站使用记录核对时间、模型和实际费用。

**完成标准：** 能找回两条聊天，磁盘上两份文件均可打开，并能核对本站用量。

常见卡点：

- **PowerShell 不认识 `/model`：** 先启动 Codex，再在任务输入区运行。
- **命令在菜单没有：** 查看 `/`，核对 CLI 版本及 `codex.cmd --help`；按原安装渠道更新，注意平台和配置差异。
- **模型选了仍 401/不可用：** 回配置课检查供应商、Key 分组、有效期和完整模型 ID，再按脱敏报错排查。
- **分叉影响原文件：** 检查是否同目录。停止并行修改同一文件，核对成果后选择不同输出文件或 worktree。
- **看不到 Git 差异：** 确认目录属于仓库且确实改动；普通文件先直接检查，不执行不懂的 Git 重置或清理。
- **压缩后细节缺失：** 将关键范围、文件名和标准写入说明或 `AGENTS.md`，在当前任务重新引用。
- **`/usage` 查不到本站余额：** 它面向 Codex 服务账户，可能要求对应认证；本站实扣费用回本站记录核对。
