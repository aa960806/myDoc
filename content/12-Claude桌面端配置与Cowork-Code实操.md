# 把 Claude 桌面端用顺手

所属栏目：Agent 与工具 → Claude 桌面端  
页面入口：`#tool/claude-desktop`  
资料核验日期：2026-11-04

先通过菜单连接只因 API，再学会选用 Chat、Cowork 和 Code。从一段会议记录到一份周报，从一个文件夹到一次可检查的修改，每一步都能跟着完成。

准备一把本站可用的 Claude 分组 API Key，以及电脑上的一个空练习文件夹。完成本课后，你应能独立配置第三方推理，用 Cowork 整理资料、用 Code 修改文件，并检查结果与本站消费。

操作顺序：安装 → 菜单配置 → 验证连接 → 选择任务模式 → 打开成果并核对消费。

## 01 安装桌面端，准备自己的练习目录

本课的“桌面端”指 Claude Desktop。它有图形界面，Code 功能可以在应用内使用；不需要为了这节课先学会终端命令。

1. 打开 [Claude 官方下载页](https://claude.com/download)，按系统选择安装包。普通 Intel / AMD Windows 电脑选择 Windows，ARM 设备选择 ARM64。
2. 安装并打开应用。本课以 Windows 菜单为例，macOS 从屏幕顶部菜单栏进入。
3. 到本站 [API 密钥](https://www.yydsapi.uno/keys) 页准备普通 Claude 分组 Key，在 [模型广场](https://www.yydsapi.uno/model-plaza) 核对模型与分组，并确认额度可用。网关根地址是 `https://www.yydsapi.uno`。
4. 在电脑“文档”中建立空文件夹 `claude-practice`。练习材料放在这里，结果集中保存到它的 `output` 子文件夹。

想使用终端的读者，可先看 [Claude CLI 教程](11-Claude-CLI常用命令与任务协作.md)。

### Cowork 的设备要求

官方第三方模式文档列出 macOS 14+，或 Windows 10 build 19041+ / Windows 11。Cowork 需要可用的硬件虚拟化；Windows 还需要 Virtual Machine Platform 和支持 Cowork 的 `.msix` 安装。首次启动可能下载工作环境，按进度等待。

Linux 有单独的 beta 安装路线，以官方说明提供的功能为准。不能运行 Cowork 虚拟机时，统一界面可能退回聊天能力。

## 02 按菜单路径连接只因 API

接下来在 Claude 应用中操作。第三方推理配置用于接入本站，密钥填写在配置窗口中。

### 第一步：启用开发者模式

点击左上角 **☰ 三个横杠 → 帮助 → 故障排查 → 启用开发者模式**。

英文菜单：**Help → Troubleshooting → Enable Developer Mode**。

### 第二步：打开第三方推理配置

再次打开左上角 **☰ → 开发者 → 配置第三方推理**。

英文菜单：**Developer → Configure Third-Party Inference…**。

### 第三步：选择 Gateway，填写 URL 与 API Key

在 **Connection** 中选择网关接入，按下表填写。已有选项正确时保持即可。

| 界面字段 | 填写内容 |
| --- | --- |
| Inference provider · 推理提供方 | `Gateway` |
| Gateway base URL · 网关地址 | `https://www.yydsapi.uno` |
| Gateway API key · 网关密钥 | 自己的本站普通 Claude 分组 API Key |
| Credential kind · 凭据类型 | `Static API key` |
| Gateway auth scheme · 认证方式 | `Bearer` |

可复制的本站根地址：

```text
https://www.yydsapi.uno
```

填写根地址，不在后面追加 `/v1/messages`。密钥完整复制，不带首尾空格。

网页配图采用 Anthropic 官方配置窗口示例，用于定位 Connection / Gateway 区域。图中示例域名不是本站地址，按本表填写。该图不作为本站已接通的证明。

### 第四步：保存并重启

点击 **Apply Changes**，出现确认窗口时点击 **Save & Restart**。重启后按登录页提示，选择使用已保存的第三方配置进入。完整的 3P 配置路线支持跳过 Anthropic 账户登录。

如果第一次重启后 Developer 菜单消失，重新执行一次“帮助 → 故障排查 → 启用开发者模式”。受管理设备可能由管理员控制该入口。

### 第五步：确认模型并测试

在模型选择器中选择本站分组允许的 Claude 模型，然后发送：

```text
你好，请用一句话介绍你能怎样帮我整理学习资料。
```

收到正常回复后，在本站 [使用记录](https://www.yydsapi.uno/usage) 中确认时间、模型和 Key。

发送测试会调用模型并按本站规则计费。保存成功说明配置已写入；收到回复且本站有对应记录，才能确认本次连接。

### CLI 与桌面端的配置关系

终端中的 `ANTHROPIC_BASE_URL` 或 `~/.claude/settings.json` 不代替上述桌面端配置。通过 Desktop 第三方模式启动的 Cowork / Code，会继承桌面端配置的供应商、地址与凭据。

**完成检查：** 应用已使用第三方配置打开，测试有正常回复，本站能查到对应记录。

## 03 按交付目标选择 Chat、Cowork、Code

| 想做的事 | 建议方式 | 本课练习 |
| --- | --- | --- |
| 问答、写作、总结一段材料 | Chat | 把会议记录变成待办 |
| 整理一批资料并生成文件 | Cowork | 生成周报与 CSV 待办表 |
| 理解项目、修改文件、运行检查 | Code | 检查并完善周报；了解代码项目检查 |

三个名称描述工作方式，不是三个不同的付费账户。

有的新版启用了 **Unified Claude**，把 Chat 与 Cowork 合在首页；支持 Cowork 的电脑会从首页开始 Cowork 会话，Code 仍是独立入口。另一些版本在 Home 的输入框内切换 Chat / Cowork，旧版可能显示独立标签。

按任务是否已添加文件夹、能使用哪些工具来辨认，不必为了找回旧按钮反复改 Key。第三方模式的功能取决于应用版本、设备条件、配置策略与网关支持。

## 04 Chat：材料、要求与追问

### 给出材料和输出格式

进入 Chat 或统一首页，将材料粘贴到输入框。有附件时先通过附件入口添加文件，再发送任务。

```text
请只根据下面的记录，整理成“结论、待办、待确认”三部分。
待办用表格，包含任务、负责人、截止时间；没有给出的信息写“待确认”，不要补猜。

记录：本周教程首页已完成，手机端还需检查。小林负责手机端检查，周五前反馈。图片教程需要换一张配图，负责人和完成时间还没定。
```

### 在同一会话修改一处

```text
保留原有事实，把待办改成可以逐项勾选的清单，并把缺少负责人或日期的条目放在最后。
```

检查它是否把未确定的负责人或日期写成了事实。纯文本可以复制保存；有可下载文件时，下载并打开检查。需要持续读写本机资料时，继续 Cowork 练习。

有效追问的三个习惯：

- 说清保留什么：“保留全部事实，只缩短句子。”
- 指出哪里不对：“第二条没有负责人，请标待确认。”
- 一轮只改一个目标：先校事实，再调语气，最后改排版。同一份材料继续当前会话，不相关的任务另开会话。

**完成检查：** 总结与原材料一致，没有提供的信息明确标为“待确认”。

## 05 Cowork：把会议记录整理成周报

本次直接读写授权的练习目录，目标是拿到两份实际文件：

- `output/weekly-report.md`
- `output/action-items.csv`

### 第一步：准备练习材料

用记事本新建 `meeting-notes.txt`，保存到 `claude-practice`，内容如下：

```text
教程项目周会记录
已完成：新手首页和 GPT 入门文字整理。
待办：小林检查手机端显示，周五前反馈。
待办：小周核对 Claude 桌面端配置步骤，周四前完成。
待办：图片教程替换配图，负责人和日期待确定。
问题：部分新手分不清 API Key 和网页登录密码。
下周重点：根据检查结果修正文案，完成一轮新手跟做。
```

### 第二步：进入 Cowork，添加文件夹

打开 Cowork；统一界面的版本从首页开始。通过文件夹选择入口添加 `claude-practice`，核对显示的路径，再允许访问。使用 Projects 时，也可新建项目并选择已有练习文件夹。

本站这条 3P 路线使用本机任务。执行时保持应用开启、电脑可用且联网；官方账户云端 Cowork 的“关闭电脑继续”不作为本课前提。

### 第三步：先确认输入和计划

```text
请确认本次可以访问的文件夹是 claude-practice。
只阅读 meeting-notes.txt，告诉我材料包含哪些内容。
我想生成一份周报和一张待办表，请先列出执行计划及目标路径，等我确认后再写文件。
不要改动原始记录；资料缺失时标为待确认。
```

核对计划是否只使用指定材料，是否把结果放进 `output`。

### 第四步：确认执行

```text
按刚才的计划执行。
在 claude-practice/output 中创建：
1. weekly-report.md：已完成、进行中、风险与下周计划。
2. action-items.csv：任务、负责人、截止时间、状态四列，使用 UTF-8。
只依据 meeting-notes.txt；信息缺失写“待确认”，不补造日期或负责人。
输出文件已存在时先问我，不覆盖。完成后给出文件路径，逐项核对内容。
```

任务通常经过读取、整理、写入和检查。出现待确认操作时核对范围再批准；需要纠正时指出要调整哪份结果。

### 第五步：打开成果并局部修改

从结果链接或系统文件夹打开周报和待办表。检查原始记录未被修改，三个待办齐全，负责人和时间没有补猜。CSV 可用表格软件导入，中文乱码时选择 UTF-8。

```text
请只把 output/weekly-report.md 的标题改为“教程项目 · 本周进展”。
保留正文事实和 action-items.csv。保存后告诉我改了哪一处。
```

### 固定工作放进项目

经常整理相同资料时，使用 **Projects → ＋ → Use an existing folder**，选择资料目录，命名为“每周工作整理”。在 **Instructions（长期指令）**中写输出目录、语言和固定格式。以后从这个项目开始会话，沿用其目录与指令。

Cowork 项目还可保存项目范围内的记忆；重要要求应核对后保留，不把自动记忆当成绝对准确的事实。项目保存在本机，与 claude.ai 上的项目分别管理，导入和账户功能以当前接入方式的入口为准。

### 进阶：定时任务、技能与连接器

先手动完成一次，再考虑定时执行。功能可用时，可以要求“每周五在这个项目中整理本周记录”，并在任务卡核对时间、时区、输入范围和输出位置。本地任务需要电脑和应用满足运行条件、本站额度足够。不能只凭“设置好了”就认定已经建立任务。

固定格式可以整理成技能；需要外部资料时再启用连接器并完成其授权。第三方模式的插件来源、连接器登录与可用工具可能受配置限制。CLI 的 `~/.claude` 技能不会自动成为 Cowork 的技能。

**完成检查：** 两份结果能打开，内容与原记录对应，第二轮只修改了周报标题。

## 06 Code：先理解项目，再修改和检查

Code 适合读项目、修改多个文件、运行检查。第一次也可只处理普通文档，不必先有代码仓库。

### 第一步：选 Local 和练习目录

打开 **Code**，开始本地 **Local** 会话，选择 `claude-practice`。核对输入框附近的目录、模型和权限。Desktop 3P Code 继承第 02 节的网关配置。

### 第二步：Plan 中先理解文件

在输入框下方权限选择器选 **Plan**。它可以读取、探索项目并提出计划，准备实施时再切换模式。

```text
请检查当前目录是否是 claude-practice。
阅读 meeting-notes.txt 和 output/weekly-report.md，检查周报是否漏掉记录中的事项。
先列出发现、依据和修改计划，不修改文件。若文件不存在，请告诉我缺少哪份。
```

### 第三步：切回 Manual，批准具体修改

核对计划后切回 **Manual**，旧版可能叫 Ask permissions。核对提示中的文件路径和操作后再允许执行。

```text
按刚才确认的计划，只完善 output/weekly-report.md。
保留已有事实，不改 meeting-notes.txt 和 action-items.csv。
缺失信息标为待确认。完成后检查原记录中的已完成事项、待办和问题是否都有对应，并给出文件路径与核对结果。
```

### 第四步：打开文件与差异

点击会话标题栏 **Files**，或点击聊天中的文件路径打开文件。右键路径里的 **Show in Explorer / Show in Finder** 可定位磁盘目录。

Git 项目可点击 **Changes**，或详情面板 Changes 卡片的新增/删除数字逐个查看差异。普通练习文件夹没有 Git 差异时，直接打开文件与原材料核对。

在差异行旁点 **＋** 可以写具体反馈，多条意见写好后 Windows 按 **Ctrl+Enter**、macOS 按 **Cmd+Enter** 提交。若支持 `/code-review`，可让它先审查，再决定是否修改。

### 第五步：代码项目运行对应检查

实际代码项目可以这样要求：

```text
先读取 README 和项目脚本，找出与本次改动相关的检查。
执行后报告结果，明确区分通过、失败和未运行的检查，并说明原因。
```

网页项目可让它按项目启动方式运行开发服务，再在 **Browser** 预览。服务卡上的 **Open** 可打开页面；确认端口和启动方式，不假定所有项目都有同一个命令。

| 功能 | 用途 |
| --- | --- |
| Plan | 先理解与讨论实施方案，执行前切换 |
| Manual | 对文件修改、命令等操作按提示确认 |
| Auto 等模式 | 可用性取决于模型、版本和管理配置，本课用 Manual 即可 |
| Files | 看文件和成果 |
| Changes | 审查文件差异 |
| Terminal | 在当前会话目录执行终端命令 |
| Browser | 预览网页与支持的文件 |

标题栏没显示某个按钮时，查看旁边的 **⋮** 菜单。

输入时可用 `@文件名` 提供项目文件，也可从 **＋** 添加附件或拖拽参考文件。运行中要立即中断可点停止按钮；发送补充要求则会在当前动作完成后读入。停止不会自动撤销已经写入的文件。

**完成检查：** 知道改了什么，能打开成果，能解释检查结论与未运行项目。

## 07 旁问、并行与协作技巧

下面主要针对 Code 的本地会话。先完成一次小任务，再逐项尝试。版本没有对应入口时，可以保留文件路径与交接摘要继续工作。

### 技巧一：用 /btw 临时问一句

在 Code 输入框输入：

```text
/btw
```

也可按 Windows **Ctrl+;** / macOS **Cmd+;**。旁问可以借用当前会话上下文，例如问“CSV 是什么”，结束后关闭并回到主任务。

旁问不会把答案自动写回主会话，关闭应用后也不保存。要采用某个结论，应明确补充到主会话。

### 技巧二：两个子代理检查，主会话汇总

```text
请用两个子代理，只读检查 output/weekly-report.md。
A 对照 meeting-notes.txt，查事实和遗漏。
B 检查结构、重复内容与待确认事项是否清楚。
都不要改文件。等两位返回后，在主会话汇总问题、依据和建议，再由我确认下一步。
```

有后台工作后，从标题栏 **⋮ → Background tasks** 查看子代理与后台命令，点条目查看输出或停止。子代理是当前会话内的分工，与侧栏另一条独立会话不同。

### 技巧三：并行会话先分清文件归属

用 **＋ New** 新建会话；Windows 快捷键 **Ctrl+N**、macOS **Cmd+N**。打开会话后点击标题重命名，例如“周报 · 事实检查”和“周报 · 表达建议”。

Windows 按住 **Alt** 点击侧栏会话、macOS 按住 **Option** 点击，可以并排查看；不同布局以当前菜单提示为准。

先让两边只读，最后由主会话统一改文件。如果必须同时写入，使用不同输出文件；Git 项目在新会话开始前打开 **Worktree**，为各自改动创建独立工作树。第三方模式未直接显示 Worktree 时，可在项目文件夹控件中查找。

默认未启用工作树时，两条会话可能共享同一目录。新会话或旁问都不会自动复制文件。

### 技巧四：让已有会话交接结果

```text
请查看已有桌面 Code 会话“周报 · 事实检查”和“周报 · 表达建议”的进展。
只汇总它们已完成的检查、依据、未解决的问题；先不要改文件。
如果其中有同名会话，请先让我确认目标。
若“周报 · 事实检查”仍缺少核对，请向这条会话发送：“请只读对照 meeting-notes.txt，检查周报事实与遗漏，完成后给出结论和对应原文。”
等检查结果齐备后，在这里汇总；本轮不让其他会话写入文件。
```

Desktop 会话列表工具主要看到它自身运行的本地、SSH、WSL Code 会话，不能据此认为它已经看到终端 CLI、VS Code 或云端会话。跨会话消息另有能力与版本要求；接收会话仍按自己的权限处理。

无法找到目标时，手动把这四项贴到另一条会话：目标、文件路径、已完成、待处理。

### 技巧五：任务卡与收尾

Claude 建议拆出独立任务时，支持的版本会显示任务卡。点击开始前，在 **Options** 核对环境、模型、目录、Worktree 和权限。需要独立任务才新开，当前问题继续原会话即可；新会话要补齐背景。

做完先检查文件和差异，再归档会话。工作树不是长期备份；要保留的 Git 改动先提交或另行保存，不依赖归档保留未提交成果。

### 技巧六：把项目习惯写成规则

代码项目可用 `CLAUDE.md` 写项目说明、运行方式与检查命令。常用流程可整理为技能，MCP 用于连接外部工具。先核对来源和访问范围，再启用。

Cowork、桌面 Code、终端 CLI 的配置来源并不完全相同，已有 CLI 技能不代表其他模式已经启用。

## 08 排错、消费与完成检查

| 现象 | 处理办法 |
| --- | --- |
| 没有 Developer 菜单，重启后消失 | 重新启用开发者模式；管理策略可能隐藏菜单或使配置窗口只读 |
| Gateway was unreachable、401、403 | 检查根地址、完整 Key、分组权限、额度和网络，先用简单文字请求验证 |
| 模型列表为空或模型不可用 | 检查本站分组和模型发现，必要时按官方 Models 设置完整模型 ID |
| Chat 能回复，Cowork 启动不了 | 检查系统、虚拟化、安装包和工作环境下载进度；再确认目录已添加 |
| Code 只给建议，不保存文件 | 看是否仍是 Plan、等待权限、目录选错或未指定输出文件 |
| 连接器、排程或云端入口不可用 | 核对当前 3P 配置、版本和功能条件；本站 Key 不自动提供官方账户的全部权益 |
| 想恢复官方账户模式 | 退出重开，在登录页选择 Anthropic 登录；经 CC Switch 管理时先切回 Official |

模型发现只自动识别部分 Claude 模型 ID。需要其他厂商模型映射时，查看 CC Switch 专节，不能把 GPT / DeepSeek 名称直接当原生 Claude 模型填入。

复杂问题记录时间、状态码、模型和脱敏提示，到“常见问题”栏目排查。不要把完整 Key 放在求助内容中。

最终确认三件事：

1. **连接可确认：** 测试有回复，本站记录能对应模型与 Key。
2. **成果能打开：** 周报与待办表已保存，文件路径和事实可核对。
3. **消费能解释：** 按练习时间查本站记录，一次 Agent 任务可能产生多次模型请求。

本站模型请求按本站规则计费。桌面端估算、官方订阅额度与本站扣费分别管理，以 [本站使用记录](https://www.yydsapi.uno/usage) 为准。
